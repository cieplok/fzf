# AGENTS.md

## Project overview

fzf is a general-purpose command-line fuzzy finder and interactive terminal toolkit. It is a Go program (`module github.com/junegunn/fzf`, Go 1.23) built from `main.go` and the packages under `src/`, with a Ruby/minitest integration-test harness in `test/`, shell integrations (Bash, Zsh, Fish, Nushell) in `shell/`, and a Vim/Neovim plugin in `plugin/`. It ships as a single static binary; there is no server, database, or web UI. The primary user-facing contract is the CLI (flags, `--bind` actions, environment variables), the shell integration scripts, the Vim plugin API, and the man pages.

## Task-routing table

| When the task involves… | Read first | Key rules |
|---|---|---|
| Fuzzy-matching algorithm, scoring, prefiltering | `src/algo/algo.go`, `src/algo/normalize.go`, `src/algo/SIMD.md` | Pure functions over `util.Chars`; every fast path has a reference implementation and an equivalence/fuzz test (`fastpath_equiv_test.go`, `runeprefilter_test.go`) — a change to an assembly fast path (`indexbyte2_*.s`, `runeindex_*.go`) must keep the fuzz targets green. Run `make bench` for perf-sensitive edits. |
| Core matching engine, event flow, concurrency | `src/core.go`, `src/matcher.go`, `src/merger.go`, `src/pattern.go`, `src/tokenizer.go` | The pipeline is `Reader → Matcher → Terminal` with `Evt*` events (see the diagram comment at the top of `core.go`). Shared state uses `src/util/atomicbool.go`, `eventbox.go`, `concurrent_set.go`; do not introduce unsynchronized cross-goroutine access. |
| CLI options, flags, usage text, `--bind` actions | `src/options.go`, `src/actiontype_string.go`, `man/man1/fzf.1`, `README.md` | `actiontype_string.go` is generated by `stringer` (`make generate`) — edit the `actionType` constants, not the generated file. A new flag or action must be documented in the man page and README in the same change. |
| TUI, terminal rendering, input handling | `src/tui/*.go`, `src/terminal.go`, `src/terminal_unix.go`, `src/terminal_windows.go` | Two backends — the built-in Light/CSI renderer (`light.go`) and `tcell` (`tcell.go`). Keep `_unix` / `_windows` variants in sync; platform-specific behavior goes behind build tags, not runtime `runtime.GOOS` checks. |
| Shell integration, completions, key bindings | `shell/common.sh`, `shell/completion.*`, `shell/key-bindings.*`, `bin/fzf-tmux`, `bin/fzf-preview.sh` | These are embedded into the binary by `shell/update.sh`; run `make fmt` (or `shell/update.sh`) after editing and `make lint` to check for drift. `shell/update.sh --check` fails the lint gate on un-synced scripts. |
| Ruby integration tests | `test/test_*.rb`, `test/lib/common.rb`, `test/runner.rb` | minitest, driven through a tmux session (`make itest` runs it in an isolated server like CI, 80×24). Uses the freshly built `bin/fzf`; env-var isolation is handled by `UNSETS` in `test/lib/common.rb`. |
| Vim / Neovim plugin | `plugin/fzf.vim`, `doc/fzf.txt`, `README-VIM.md` | Vim help is generated from `doc/fzf.txt`; keep `README-VIM.md` and the help file consistent with the plugin API. |
| Build, packaging, release, installers | `Makefile`, `.goreleaser.yml`, `install`, `install.ps1`, `RELEASE.md`, `CHANGELOG.md` | `make build` uses goreleaser; `make release` runs on `master` only and requires `GITHUB_TOKEN`. `make prerelease` asserts version strings agree across `CHANGELOG.md`, `man/man1/*.1`, `install`, and `install.ps1`. |
| CI workflows | `.github/workflows/*.yml` | `linux.yml` is the authoritative gate: `make lint` → `make test` → fuzz → integration. Mirror CI locally when changing the gate. |

## Validation gate

Run before opening or updating a PR, in order:

- `go build ./...`
- `make test`

Additional commands used by CI but not part of the local gate: `make lint` (needs `rubocop` + `shfmt`), `make itest` (needs `tmux` + `bundle install`), and the fuzz targets. See `SDLC.md` for how the gate gates review sign-off.

## Conventions

- Go code is `gofmt -s` formatted; the lint gate fails on unformatted files (`make lint`).
- Tests live next to the code they cover as `*_test.go`; the Ruby integration tests are the end-to-end layer.
- Never commit built binaries (`bin/fzf`, `target/`, `dist/` are gitignored).
